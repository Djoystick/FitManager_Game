# FitManager Server Migration & Infrastructure Plan

> **Goal:** Migrate FitManager from Vercel & Supabase Cloud to a standalone dedicated VPS (Virtual Private Server) to support high-performance Match Engine simulations, eliminate serverless execution timeouts, and maintain a fixed budget.

## 1. Budget & Target Specs
- **Monthly Budget:** ~1500 RUB / month ($15 USD)
- **Target Providers:** Timeweb Cloud, Aeza, Selectel, or FirstVDS
- **Target Hardware:** 4 to 6 vCPU cores, 8-12 GB RAM, 80+ GB NVMe SSD.

## 2. Infrastructure Architecture ("All-In-One" Setup)

With 8-12 GB of RAM available, the system will use a robust enterprise-grade monolithic deployment, avoiding the overhead of heavy orchestration tools.

### A. PostgreSQL 15+ (Database)
- **Role:** Core data store.
- **Tuning:** Configured via `postgresql.conf` to utilize 4 GB RAM for `shared_buffers`. This ensures the entire active database (players, market, league standings) resides in RAM for sub-millisecond query resolution.
- **Migration:** Dump data from Supabase Cloud (`supabase db dump`) and restore on the VPS.

### B. PostgREST
- **Role:** REST API layer over PostgreSQL.
- **Purpose:** Next.js application relies on `@supabase/supabase-js`, which expects the Supabase REST API format. PostgREST (written in Haskell, consuming ~50MB RAM) perfectly mimics this layer without requiring the entire Supabase Docker stack.

### C. Redis (In-Memory Cache)
- **Role:** High-speed volatile cache.
- **Purpose:** Used for caching active market listings and league standings to prevent DB locking during massive concurrent reads.

### D. Next.js App Router (Game Backend & Frontend)
- **Role:** Serves React components, Server Actions, and Match Engine simulations.
- **Setup:** Deployed using Node.js standalone build. Managed by **PM2** (Process Manager) running in cluster mode across multiple CPU cores.
- **Benefit:** Eliminates Vercel's 10-60s Serverless timeouts, allowing complex 15-tier league simulations to complete successfully in the background.

### E. Nginx
- **Role:** Reverse Proxy & SSL Termination.
- **Setup:** Routes traffic to Next.js (`/`) and PostgREST API (`/rest/v1`). Certbot automatically manages Let's Encrypt SSL certificates.

## 3. CI/CD Deployment Flow (GitHub Actions)

Zero-downtime automated deployment will be implemented to retain Vercel-like Developer Experience.

1. **Push:** Developer runs `git push origin main`.
2. **Action Triggered:** GitHub Actions workflow intercepts the push.
3. **SSH Access:** The Action securely connects to the VPS via SSH keys.
4. **Build Phase:** Pulls the latest code, runs `npm ci` and `npm run build`.
5. **Reload:** Executes `pm2 reload fitmanager`. PM2 gracefully restarts the Next.js cluster workers one by one, ensuring players currently online do not experience downtime.

## 4. Migration Execution Steps
*To be executed when nearing Beta Release or when Supabase free-tier limits are reached.*

1. Rent VPS with Ubuntu 24.04 LTS.
2. Install Docker, Node.js (via NVM), PM2, and Nginx.
3. Run `docker-compose.yml` (to be created) to spin up PostgreSQL, PostgREST, and Redis.
4. Apply Supabase Database Dump.
5. Clone repository, setup `.env.local` (change `NEXT_PUBLIC_SUPABASE_URL` to local PostgREST IP).
6. Build and launch Next.js via PM2.
7. Point DNS (A Record) to the new VPS IP.
8. Configure Nginx and SSL.
