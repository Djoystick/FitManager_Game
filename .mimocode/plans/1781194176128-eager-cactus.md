## Итоговая сводка

Движок (`app/utils/matchEngine.ts`, 778 строк) — **Swiss Watch Architecture v3.0** — функционален, но содержит несколько серьёзных механических проблем, которые делают симуляцию предсказуемой и недостаточно динамичной. Ниже — подробный разбор.

## 1. НАЙДЕННЫЕ СЛАБЫЕ МЕСТА В ФОРМУЛАХ

### 1.1 `duel()` — Сигмоида с фиксированным bias (строка 97–104)

```ts
const raw = 1 / (1 + Math.exp(-0.045 * diff)) + attackerBias;
const p = Math.min(0.97, Math.max(0.03, raw));
```

**Проблемы:**
- **attackerBias = +0.08 всегда.** Атакующая сторона ВСЕГДА получает +8% к шансу победы. Это делает домашнее/выездное преимущество неявным, но оно всегда работает в пользу атакующего — нет контекста (счёт, время, тактика).
- **k = 0.045 слишком мягкий.** Разница в 40 единиц OVR даёт ~96% шанс. Но в реальном футболе даже очень сильные команды проигрывают слабым. Нужна большая вероятность апсетов (например, k = 0.035).
- **Нет "momentum" factor.** Дуэли не зависят от текущего счёта — команда,领先的 2:0, атакует с той же вероятностью, что и проигрывающая.

### 1.2 `staminaMult()` — Ступенчатая функция (строка 107–114)

```ts
if (s >= 75) return 1.00;
if (s >= 50) return 0.95;
// ...
return 0.60;
```

**Проблема:** Ступенчатая (каскадная) функция создаёт **резкие скачки** на границах. Игрок с 76 стамины = 100% эффективности, а с 74 = 95%. Это нереалистично и не даёт плавного деградирования. Нужна линейная или квадратичная интерполяция.

### 1.3 `eff()` — Буферы не складываются логично (строка 121–146)

```ts
buffMult = 1.0;
if (hasGreenLink) buffMult += 0.10;
if (hasSynergy)   buffMult += 0.10;
buffMult = Math.min(1.35, buffMult);
if (hasConflict) {
  buffMult = 1.0 + (buffGain * 0.5);
  buffMult *= 0.85;
}
```

**Проблемы:**
- Green link + synergy = +20%, но cap = 35%. Разница между 20% и 35% пустует — нет механики, которая бы использовала этот диапазон.
- Conflict халфует буферы, но -15% penalty применяется ДО этого. Порядок operations: `(1 + gain*0.5) * 0.85`. Это означает: при полном буфере (1.35) + conflict = `1 + 0.35*0.5 = 1.175 * 0.85 = 0.999` — игрок с conflict и полным буфером оказывается примерно на уровне 1.0. **Conflict фактически нейтрализует ВСЕ буферы, но не снижает базовый стат.** Это слишком мягкий penalty.

### 1.4 `drainStamina()` — Статичная (строка 207–233)

```ts
let base = Math.floor(Math.random() * 7) + 16; // 16–22
```

**Проблемы:**
- Drain одинаковый для **всех минут** матча. В реальном футболе первые 30 минут тратят больше энергии (прессинг), последние — меньше (экономия).
- Нет разницы между позициями除了 GK и MID. Нет разницы между FWD и DEF.
- Нет привязки к темпу матча. Если команда много атакует — больше бега → больше стамина. Сейчас drain зависит только от possession.

### 1.5 `buildTimeline()` — Атаки не привязаны к минутам (строка 535–569)

**Проблема:** Минуты 2–88 перемешиваются случайно. Это значит, что атаки могут идти подряд (минуты 45, 46, 47) или с большими промежутками (минуты 30, 80). Нет фазового节奏: обычно в реальном футболе больше атак в начале и конце тайма.

### 1.6 `midfieldScore()` — Упрощённый (строка 239–255)

```ts
return pool.reduce((sum, p) =>
  sum + get(p, safeNum(p.stats.passing, 50)) +
  get(p, safeNum(p.stats.dribbling, 50)) +
  get(p, safeNum(p.stats.physical, 50) * 0.4), 0);
```

**Проблема:** Passing и Dribbling учитываются как сумма. Но в реальном футболе control midfield — это не просто сумма навыков, а **баланс** между ними. Команда с 3 playmaker'ами (все high passing, low physical) будет доминировать в possession, но будет уязвима физически. Сейчас это не моделируется.

### 1.7 `resolveAttack()` — 3 фазы без обратной связи

Attack resolver имеет 3 фазы: Build-up → Penetration → Finishing. Каждая фаза — **независимый дуэль**. Если команда выиграла Build-up, она автоматически идёт в Penetration. Нет шанса "сбросить мяч" после перехвата. Нет counter-attack механики.

### 1.8 `maxGoals` cap — Непрозрачный (строка 662–665)

```ts
const maxGoals = ovrDiff >= 20 ? 8 : ovrDiff >= 10 ? 6 : ovrDiff >= 5 ? 5 : 4;
```

**Проблема:** Это жёсткий лимит на голы, но он зависит только от разницы OVR. Не учитывает ни стиль игры, ни тактику, ни форму игроков. Команда с 4-3-3 и high pressing должна забивать больше, чем 4-5-1 low block — но сейчас нет этой разницы.

## 2. ОТСУТСТВУЮЩИЕ МЕХАНИКИ

### 2.1 Тактики (Tactical Styles) — КРИТИЧЕСКИ ОТСУТСТВУЕТ

**Текущее состояние:** Нет. Совсем. Игрок не может выбрать стиль игры.

**Предложение — 6 тактик:**

| Тактика | Эффект на possession | Эффект на атаки | Эффект на защиту | Риск |
|---------|---------------------|-----------------|------------------|------|
| **Tiki-Taka** | +15% possession | -1 атака | -1 защитный дуэль | Уязвимы к контратакам |
| **Counter Attack** | -10% possession | +2 атаки после перехвата | +1 защитный дуэль | Мало владения |
| **High Press** | +5% possession | +1 атака | -0.5 защитный дуэль | Больше стамина |
| **Park the Bus** | -15% possession | -2 атаки | +2 защитный дуэль | Почти не атакуют |
| **Wing Play** | +5% possession | +15% шанс wing assist | -0.5 защитный дуэль | Уязвимы по центру |
| **Balanced** | 0 | 0 | 0 | Нет бонусов, но и нет рисков |

**Реализация:** Тактика передаётся в `simulateMatch()` как параметр. Модифицирует `homePoss`, количество атак, и вероятность wing assist.

### 2.2 Домашнее преимущество (Home Advantage)

**Текущее состояние:** `attackerBias = 0.08` — это единственное "преимущество". Оно одинаково для обеих команд при владении.

**Предложение:** 
- Home team получает +5% ко всем статам (маленький, но ощутимый бонус)
- Home team получает +1 атаку за матч
- Home crowd noise увеличивает шанс пенальти для home team на 3%

### 2.3 Momentum / Давление счёта

**Текущее состояние:** Нет. Команда,领先的 3:0, атакует с той же вероятностью, что и проигрывающая 0:3.

**Предложение:**
- Команда, проигрывающая с разницей ≥2, получает +10% к атакам (desperation push)
- Команда,领先的 с разницей ≥3, получает -5% к атакам (comfort zone)
- В последние 15 минут (75+), проигрывающая команда получает额外 +1 атаку

### 2.4 Stamina Drain по фазам матча

**Текущее состояние:** Одинаковый drain от минуты 1 до 90.

**Предложение:**
```
Фаза 1 (1–30 мин):   drain × 1.2 (интенсивный старт)
Фаза 2 (31–60 мин):  drain × 1.0 (нормальный темп)
Фаза 3 (61–75 мин):  drain × 0.85 (экономия энергии)
Фаза 4 (76–90 мин):  drain × 1.1 (финальный спурт)
```

### 2.5 Жёлтые/Красные карточки — Улучшенная система

**Текущее состояние:** Карточки появляются только при фолах (5% шанс). Красная = удаление. Жёлтая = ничего не делает.

**Предложение:**
- **2 жёлтые = красная.** Нужно трекать количество жёлтых карточек.
- **Жёлтая карточка снижает aggression защитника на 15%** (боится второй жёлтой → менее жёсткие подкаты)
- **Удалённый игрок:** Команда играет в меньшинстве. Все атаки против них получают +8% bonus.
- **Фолы с карточкой после 75-й минуты:** Увеличенный шанс красной (60% вместо 20%).

### 2.6 Индивидуальные трейты — Расширение

**Текущее состояние:** 6 трейтов: Playmaker, Poacher, Engine, Speedster, Anchor, Wall.

**Предложение — 6 новых:**

| Трейт | Эффект |
|-------|--------|
| **Comeback Kid** | +15% ко всем статам когда команда проигрывает |
| **Clutch** | +20% к finishing в последние 15 минут |
| **Tireless** | -40% drain stamina (вместо -30% у Engine) |
| **Enforcer** | +10% к defend duels, но +5% шанс фола |
| **Aerial Threat** | +25% к угловым, +15% к голам головой |
| **Dive King** | +5% шанс пенальти при атаке (моделирует симуляцию) |

### 2.7 Счётчики атак — Более реалистичные

**Текущее состояние:** `5 + possession * 7 + jitter`. Итого 3–12 атак.

**Предложение:**
- Базовые атаки: 4–6 (вместо 5)
- Possession bonus: ×8 (вместо ×7)
- Формация модификатор: 4-3-3 = +1 атака, 5-4-1 = -1 атака
- Стиль: Tiki-Taka = -1, Counter Attack = +1
- Домашнее преимущество: +1

### 2.8 События матча — Больше драматизма

**Текущее состояние:** Гол, saves, fouls, injuries, substitutions.

**Предложение — новые события:**

| Событие | Шанс | Эффект |
|---------|------|--------|
| **Offside** | 10% от успешных penetration | Атака обнуляется, потеря минуты |
| **Crossbar** | 5% от finishing | Шанс гола снижается на 50% (не 100% как miss) |
| **Own Goal** | 2% при низком OVR defend | Гол в свои ворота |
| **Penalty Save** | Базовый 35% для GK | GK угадывает угол |
| **Last-minute Goal** | ×1.5 шанс для проигрывающей команды в 85+ мин | Драматизм |

### 2.9 Матчевая форму (Match Form) — Нетривиальный RNG

**Текущее состояние:** Чистый RNG через `Math.random()`.

**Предложение:** Ввести **"form streak"** модификатор:
- Последние 3 матча: все победы → +5% ко всем статам (confidence boost)
- Последние 3 матча: все поражения → -5% ко всем статам (tilt)
- Это не сохраняется — вычисляется на лету перед каждым матчем

## 3. АНАЛИЗ МАТЕМАТИЧЕСКОЙ КОРРЕКТНОСТИ

### 3.1 Владение (Possession)

**Формула:** `homePoss = homeMid / (homeMid + awayMid)`

Где `midfieldScore` = сумма passing + dribbling + physical×0.4 для всех MID игроков.

**Проблема:** Суммирование НЕ нормализовано. Команда с 5 MID игроками будет иметь possession ~60%, даже если каждый MID — слабый. Команда с 3 MID — будет иметь ~40%, даже если они суперзвёзды.

**Исправление:** Делить на количество MID игроков: `midfieldScore / mids.length`.

### 3.2 Количество атак

**Формула:** `Math.round(5 + homePoss * 7 + Math.random() * 2 - 1)`

**Проблема:** Jitter ±1 слишком мал. При homePoss = 0.55, это 5 + 3.85 + jitter ≈ 9. При homePoss = 0.45, это 5 + 3.15 + jitter ≈ 8. Разница в 1 атаку — слишком мало для meaningful impact.

**Исправление:** Увеличить jitter до ±2 и добавить formation modifier.

### 3.3 Win Probability

Общая вероятность выигрыша = произведение вероятностей победы в каждой фазе.

**Проблема:** Вероятности не dependent. Если команда выиграла Build-up, она идёт в Penetration, и если выиграла — в Finishing. Это multiplicative: `P(win) = P(build) × P(penetrate) × P(finish)`. При средних статах: `0.55 × 0.55 × 0.55 = 0.166` — только 16.6% шанс забить за атаку. Это нормально, но проблема в том, что **ни одна фаза не усиливает другую**. Нет "momentum" после успешного build-up.
