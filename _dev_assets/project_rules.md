## Microsoft AI Engineering Standards
Следующие принципы, основанные на лучших практиках из репозитория `microsoft/AI-Engineering-Coach`, ОБЯЗАТЕЛЬНЫ к применению в проекте FitManager:

1. **Spec-Driven Development (Нет Vibe Coding'у):** 
   - Любое значимое изменение или написание логики должно начинаться с четкого плана (Plan Mode). Запрещено "писать код вслепую" без понимания конечной архитектуры.
2. **Security & Review First (Без YOLO Mode):**
   - Строгий аудит любого сгенерированного кода, особенно в части Server Actions (Next.js) и API роутов. 
   - Выполнение терминальных команд и миграций базы данных возможно только после предварительного обдумывания последствий (No Auto-Approve).
3. **Строгая типизация и обработка ошибок:**
   - Всегда использовать Typescript интерфейсы для обмена данными между клиентом и сервером. Любой запрос к БД (Supabase) должен оборачиваться в try/catch с консистентным UI-фидбеком для пользователя.
4. **Оптимизация контекста (Context Hygiene):**
   - Использовать только релевантные файлы для контекста задачи, избегать слепого копирования огромных блоков кода или логов, чтобы предотвратить галлюцинации и "размытие" инструкций.
5. **UI/UX & Плавность (View Transitions):**
   - Обязательно использование View Transitions API (или framer-motion/Tailwind переходов) для обеспечения плавного, нативного UX при переключении страниц и табов. Никаких резких скачков интерфейса.

**ИНСТРУКЦИЯ АГЕНТУ:** При возникновении сложных архитектурных задач, сомнений в паттернах проектирования или настройке CI/CD, ты автоматически ОБЯЗАН обращаться к файлам внутри директории `.ai-tools/AI-Engineering-Coach` (в частности, в `src/core/rules/`) за референсами и контекстом, прежде чем предлагать решение.
